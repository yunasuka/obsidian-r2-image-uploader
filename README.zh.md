# Cloudflare Image Uploader

[English](README.md)

把笔记里的图片存进你自己的 [Cloudflare R2](https://developers.cloudflare.com/r2/) 存储桶。

剪藏下来的网页文章，图片其实只是一个指向原网站的链接：原作者删帖、网站关掉，你笔记里的图也就没了。这个插件会把这些图下载下来存进你的存储桶，再把笔记里的链接换成你自己的。粘贴、拖进来的图片也会直接传上去，不占库的空间。

## 功能

**网络图片（剪藏的文章）**
- **新剪藏自动转存**：监视的文件夹（默认 `Clippings`，Obsidian Web Clipper 默认存这里）里出现新笔记，几秒后自动把里面的网络图片转存到 R2；从手机同步过来的新笔记也会处理。这个开关按设备生效，在一台经常开着的电脑上打开就够了。
- **从网页复制粘贴后**，马上转存其中的图片。
- **命令**：转存当前笔记、转存所有笔记（先显示数量，最后列出下载不到的图片，这些保留原链接）。
- **记住原地址**：每张转存的图都记下它原来的网址（存在插件的 `data.json` 里），命令「把当前笔记的图片换回原网络链接」可以换回去（R2 里的副本还在）。
- 下载有礼貌：每个网站同时最多 2 个请求，被限流会等一会再试；用浏览器的 User-Agent，遇到防盗链会带上来源再试一次。代码块里的链接不动。

**本地图片**
- **粘贴 / 拖入即上传**，上传时先显示占位符。
- **不会丢图**：传不上时先按普通附件存到本地，之后自动补传（启动时、每 5 分钟、网络恢复时），传上去后自动改链接、清掉本地临时文件。
- **上传本地图片**：当前笔记或整个库，保留显示尺寸和说明文字（`![[a.png|300]]` → `![|300](https://…)`）。

**通用**
- **文件名用内容哈希**（默认 `{hash}.{ext}`）：同一张图只存一份，链接永远不变。
- **可选转 WebP**：转完没变小就传原图；GIF、SVG 不转。
- 密钥默认只存在本机（Obsidian 密钥存储），也可以选「密钥随库同步」。
- 电脑和手机都能用；没有第三方依赖，签名用 Web Crypto 自己实现；走 Obsidian 的 `requestUrl`，存储桶不用配 CORS。

## 配置

1. **建存储桶**：Cloudflare 后台 → R2 对象存储 → 创建存储桶。
2. **开公开访问**：存储桶 → 设置 → 自定义域 → 绑一个托管在 Cloudflare 上的（子）域名，比如 `img.example.com`。`r2.dev` 地址也能用，但有限速，只适合测试。
3. **建 API 令牌**：R2 → 管理 API 令牌 → 创建帐户 API 令牌 → 权限选「对象读和写」，只给这个存储桶。记下「访问密钥 ID」和「机密访问密钥」。
4. 在 Obsidian：设置 → Cloudflare Image Uploader，填账户 ID、存储桶、两个密钥和公开访问地址，点「测试」（会上传一个小文件，从公开地址读回来，再删掉）。
5. 在「网络图片」里，在想用的设备上打开自动转存，确认监视的文件夹。

## 使用方法

配置好以后，日常基本不用管它。几种常见场景：

**1. 用 Web Clipper 剪藏文章**
在浏览器里用 Obsidian Web Clipper 剪藏，笔记存进 `Clippings` 文件夹。几秒后插件会自动把文章里的图片下载、存进你的 R2，右下角提示「已转存……张网络图片」。笔记里的图片链接变成你自己的域名，原文章删了也不受影响。
> 需要先在设置「网络图片」里打开「新笔记自动转存网络图片（本设备）」。有多台设备的话，在一台经常开着的电脑上打开就够了，手机剪藏的笔记同步过来后也会被它处理。

**2. 从网页复制一段粘贴进笔记**
粘贴后插件会马上把这段内容里的图片转存。

**3. 截图或拖图片进笔记**
截图后直接粘贴，或者把图片文件拖进笔记，插件会上传到 R2 并插入链接，图片文件不再存进库里。没网时先存在本地，有网后自动补传。

**4. 处理以前的笔记**
打开设置页最下面的「工具」：
- 「把所有笔记的网络图片转存到 R2…」：把以前剪藏的文章里的图片一次性存下来。先显示要处理多少张，点「开始」才执行；跑完会列出下载不到的图片（一般是原网站已经删了）。
- 「上传整个库的本地图片…」：把库里已有的本地图片传到 R2。
只想处理一篇的话，打开那篇笔记，按 `Ctrl/Cmd + P` 搜「R2」，用对应的「当前笔记」命令。

**5. 想换回原来的链接**
打开笔记，运行「把当前笔记的图片换回原网络链接」。R2 里的副本还在，随时可以再转存回来。

**6. 删笔记会不会删图？**
不会。插件只往 R2 里加图片，从不删除，所以误删的笔记从回收站恢复后图片照样能显示。

## 命令

整库的两个命令在设置页「工具」里也有入口。

| 命令 | 作用 |
|---|---|
| 把当前笔记的网络图片转存到 R2 | 下载当前笔记里的网络图片存进 R2，改写链接 |
| 把所有笔记的网络图片转存到 R2… | 对所有笔记做同样的事，先显示数量，最后列出失败的 |
| 上传当前笔记里的本地图片 | 把当前笔记嵌入的本地图片上传，改写嵌入 |
| 上传整个库的本地图片… | 对所有笔记做同样的事，先显示数量 |
| 补传上传失败的图片 | 立即补传因为上传失败而先存在本地的图片 |
| 把当前笔记的图片换回原网络链接 | 把转存过的图换回它原来的网址 |
| 停止正在进行的任务 | 整库任务处理完当前笔记就停，再运行一次会接着处理 |

失败两次的网络图片，自动转存会跳过（手动命令仍会再试；设置里可以清空记录）。被限流、网络出错不算失败。

用命令上传**本地**图片后，本地文件默认保留。把「上传本地文件后」改成「移到回收站」就会清掉；只有在没有任何笔记或白板再提到这个文件时才会删。

## 文件名模板

默认 `{hash}.{ext}`。可用占位符：`{hash}`（上传内容 SHA-256 的前 16 位）、`{hash:N}`、`{ext}`、`{name}`（原文件名）、`{year}`、`{month}`、`{day}`、`{timestamp}`。斜杠可以分文件夹，比如 `notes/{year}/{month}/{hash}.{ext}`。

模板里有 `{hash}` 时，已经存在的图不会重复上传；没有 `{hash}` 时，遇到同名文件绝不覆盖，而是在文件名后面加时间戳。

## 隐私和安全

- **联网**：插件连你的 R2 S3 接口（`https://<账户 ID>.r2.cloudflarestorage.com` 或你填的地址）、「测试连接」时访问你的公开地址，以及笔记里网络图片所在的网站（只为下载这些图片）。不收集任何数据。
- **上传的图片，拿到链接的人都能打开。** R2 不允许别人列出存储桶里的文件，哈希文件名也猜不到，但不要上传不能通过链接分享的内容。
- 默认密钥存在每台设备自己的 Obsidian 密钥存储里（每台设备填一次）。也可以打开「密钥随库同步」：密钥以明文存进插件的 `data.json`，跟着插件一起同步到其他设备（Obsidian Sync 开了插件同步、网盘、git 等）。只在同步渠道是自己私有的情况下这么做。无论哪种，都建议用只能访问图床存储桶的令牌。
- 转存的网络图片供你自己存档用，请尊重原作者的权利。

## 开发

```bash
npm install
npm run dev        # 监听构建 main.js
npm test           # 单元测试（SigV4 用 AWS 官方测试向量、命名、链接解析和改写）
npm run build      # 类型检查 + 生产构建
npm run install-vault -- /path/to/vault   # 把 main.js、manifest.json、styles.css 拷进库里
```

R2 真实往返测试（`test/r2.e2e.test.ts`）只在存在 `.env.local`（含 `R2_ACCOUNT_ID`、`R2_BUCKET`、`R2_PUBLIC_URL`、`R2_ACCESS_KEY_ID`、`R2_SECRET_ACCESS_KEY`）时运行。

发版：改 `manifest.json`、`package.json`、`versions.json` 里的版本号，`npm run build`，再建一个 tag 和版本号相同的 GitHub Release（比如 `1.0.1`），附上 `main.js`、`manifest.json`、`styles.css`：

```bash
gh release create 1.0.1 main.js manifest.json styles.css --title 1.0.1 --notes "..."
```
